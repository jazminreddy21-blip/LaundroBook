What's Changed Since the Previous README

PRIORITY WASH (QUICK IS NOW PRIORITY):

Quick Wash is now called Priority Wash everywhere. The wash types are
priority, normal and heavy. The booking form, the price lookup in
prices.json, the duration labels in booking.js and the server-side
validation in bookingController.php all use the new name. The emails
and tracking pages pick it up on their own because they print the wash
type straight from the database.

Prices: Priority is R50 for clothes, R65 for beddings and R55 for
towels.

The database needed the change too. The service table's wash type check
only allowed 'quick', so it had to be dropped and re-added. If you
already have a database, run seeder/rename_quick_to_priority.sql once.
It renames the existing rows in place, so old bookings keep working. It
is safe to run twice.


DATABASE FILES (seeder FOLDER):

The setup is now two files that you run one after the other in the SQL
tab in phpMyAdmin: seeder/databaseQuery.sql first, then seeder/seed.sql.

While getting the schema to import I fixed two problems. A stray comma
before the next statement was a syntax error, the schema also allows 'priority' now.

seed.sql adds the admin login (admin / Test@123), three machines, six
slots with full date-times, the nine services with the new prices and
three groundworkers. Run it only once, or you'll get duplicate rows.


DELIVERY TIME ESTIMATES:

Bookings now show estimated times. They are fixed placeholder numbers,
not live scheduling, but they are set to look realistic for each
service and load type. All of them live in Config/DeliveryTimes.php, so
one file changes everything.

Priority clothes and towels are same day. Everything else takes one or
two days:

  Priority: clothes same day, beddings 1 day, towels same day
  Normal:   clothes 1 day, beddings 2 days, towels 1 day
  Heavy:    clothes 1 day, beddings 2 days, towels 2 days

Same day jobs are ready after the wash plus drying and folding time,
with a one hour delivery window shortly after. Jobs that take a day or
more are ready at 09:00 and delivered between 10:00 and 11:00 on that
day. Pickup is an hour before the first slot. A Heavy Wash uses the end
of its second slot.

The work is done by the new Services/DeliveryEstimator.php.
BookingService uses it for the pickup and delivery times saved with the
booking, replacing the old fixed 1 hour and 2 hour offsets.

Customers see it in four places: the confirmation page and the
confirmation email show the estimated pickup and delivery window (or
"ready for collection from" for self drop-off), the order tracking page
shows an estimated ready time, and the delivery and pickup tracking
pages now show a window instead of a single time.


PAYMENT NOTE:

Under Collection Method on the booking form there is now a short note
that changes with the choice. For Home Pickup and Delivery, the
customer pays when the washed laundry is brought back. For Self Drop
off and Pickup, they pay in store. No payment is taken online.


CONFIRMATION PAGE (LATER CHANGE):

I removed the Duration row from the confirmation page. It also shows
the estimated times described above.


PHONE NUMBER VALIDATION:

The browser accepted 7 to 15 digits but the server needed exactly 10,
so a number with 12 digits passed the form and was then rejected. The
browser now checks for exactly 10 digits as well. I also fixed the
typo "conatin" in the server's name error message.


GROUNDWORKER MANAGEMENT (SUPER ADMIN ONLY):

There is a new Groundworkers page where the super admin can add and
remove drivers and collectors, with a link in the nav on every admin
page. Other admins are sent back to the dashboard, and anyone who isn't
logged in goes to the login page.

Adding checks the name length, a valid phone number, that the phone
number isn't already used, and that the role is driver or collector.
Removing is blocked for the last groundworker and for anyone who has
pickup or delivery records, because those rows point to them.

I also changed automatic assignment. It used to pick the first
groundworker, so anyone added later never got any work. It now picks
the groundworker with the fewest open jobs. When two are tied, the one
with the lowest ID wins. It doesn't look at the role yet.


AFTER PULLING, NEED TO:

1. Replace JS/prices.json (it now has the priority prices).
2. If your database already exists, run
   seeder/rename_quick_to_priority.sql once. For a fresh start, drop
   the database and run seeder/databaseQuery.sql and then
   seeder/seed.sql instead.
3. Copy the two new files, Config/DeliveryTimes.php and
   Services/DeliveryEstimator.php. The names and the capital letters
   matter.
4. Check that bookingController.php has the session lines for the
   estimated times (ready_text, window_text, pickup_text and
   is_delivery).
5. Hard refresh the browser, or the old CSS and JavaScript will show.
